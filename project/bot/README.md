# Telegram-бот «Что сказать, когда…»

Бот проекта с разборами трудных ситуаций с детьми. **С клиентами общается только ИИ-помощница «Виктория»** — опытный «менеджер по продажам и заботе о клиентах», который честно говорит, что он программа. Владелица (автор) с клиентами не переписывается: всё, что требует её действий, приходит раз в неделю одной сводкой. Роль, правила и 12 примеров диалогов Виктории — в [`VICTORIA.md`](VICTORIA.md).

Что делает бот:

- **/start**: Виктория представляется («Я Виктория — ИИ-помощница проекта…»), просит согласие на обработку персональных данных и присылает бесплатный PDF «10 фраз, которые останавливают ссору с ребёнком». Потом спрашивает, присылать ли новости, и показывает меню.
- **Меню** (две кнопки):
  - «Разборы»: три разбора по 299 ₽ и набор за 690 ₽, у каждого описание и кнопка оплаты.
  - «Спросить Викторию»: ИИ-помощница на GigaChat, а без ключа — готовые ответы из `faq.json`.
  - Личных консультаций и кнопки «Написать автору» нет (решение владелицы).
- **Сервисные сценарии Виктории** (`support.py`, фиксированные тексты, работают и без ИИ): файл не пришёл (повторная отправка), «не подошло» (замена на другой разбор, для набора — подарок «Карта спокойного вечера»), возврат (замена один раз → если настаивает, заявка по e-mail оплаты), жалоба, мат, просьба «позвать человека».
- **Советы после «10 фраз»** (только с согласием на рассылку): три коротких сообщения в первые три вечера, затем «Как прошла неделя?» после покупки. Подробно — раздел 7а. Отписка — `/stop_tips`.
- **Еженедельная сводка владелице** (понедельник 10:00 МСК, одно сообщение): новые пользователи, покупки, замены, заявки на возврат (user_id, e-mail оплаты, дата покупки, продукт), кому выдать файл, вопросы, на которые не нашлось ответа. Раздел 7б.
- **Безопасность**:
  - Если человек пишет о желании умереть, самоповреждении или насилии, бот ничего не продаёт и отвечает заранее написанным текстом с телефонами 8-800-2000-122 и 112. Уведомление владелице — только если `NOTIFY_OWNER_ON_CRISIS=1` (по умолчанию выключено).
  - После заявки на возврат человек получает отметку **no_sell навсегда**: никаких продаж, цепочек, карточек, кнопок оплаты.
  - Действуют ограничение длины сообщения и защита от спама.
- **Данные**: хранится минимум — Telegram ID, имя из профиля, дата согласия, согласие на новости, что выдано; e-mail — только если человек сам оформил возврат или «файл не пришёл». Данные детей бот не спрашивает и не хранит. Команда **/delete_me** удаляет всё, кроме невыполненной заявки на возврат и отметки no_sell.

> Важно. Виктория — ИИ, а не психолог и не служба экстренной помощи. Кризисный детектор работает как сеть безопасности, но может что-то пропустить. Регулярно читайте журнал диалогов и пополняйте список слов (раздел «Безопасность»).

## 2. Создать бота у BotFather

1. В Telegram найдите **@BotFather** (с синей галочкой) и нажмите «Начать».
2. Отправьте `/newbot`.
3. Введите имя бота, например «Что сказать, когда…».
4. Введите адрес бота латиницей, он должен заканчиваться на `bot`, например `chtoskazat_bot`.
5. BotFather пришлёт **токен** вида `1234567890:AAH...`. Это пароль от бота: никому не пересылайте его и не публикуйте.
6. По желанию: `/setdescription` (описание), `/setuserpic` (аватар).

**Ваш Telegram ID** (OWNER_ID): напишите боту **@userinfobot**, он пришлёт число `Id`. Обязательно нажмите `/start` в своём новом боте, иначе он не сможет присылать вам уведомления.

## 3. Подготовить файлы

Положите PDF в папку `files/` с такими именами (имена можно поменять в `.env`):

```
files/00-lead-magnet.pdf   бесплатные «10 фраз»
files/01-telefon.pdf       Разбор 1
files/02-podrostok.pdf     Разбор 2
files/03-uroki.pdf         Разбор 3
files/04-podarok.pdf       подарок «Карта спокойного вечера» (вместо замены для набора)
```

Если файла нет, бот не упадёт: Виктория скажет пользователю, что пришлёт файл позже, а вам придёт техническое уведомление «нет файла» (это не переписка с клиентом).

## 4. Запустить на своём компьютере (для проверки)

Нужен Python 3.11 или новее (python.org → Downloads; на Windows при установке поставьте галочку «Add Python to PATH»).

Откройте терминал (Windows: «Командная строка»; Mac: «Терминал») в папке `bot`:

```bash
# 1. Создать отдельное окружение (один раз)
python -m venv .venv            # на Mac/Linux может быть python3

# 2. Включить его
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Mac / Linux

# 3. Установить библиотеки (один раз)
pip install -r requirements.txt

# 4. Создать файл настроек
copy .env.example .env          # Windows
cp .env.example .env            # Mac / Linux
```

Откройте `.env` в Блокноте и заполните минимум `BOT_TOKEN` и `OWNER_ID`. Ссылки на оплату (`PAY_LINK_TELEFON` и т. д.) должны начинаться с `https://`. `NOTIFY_OWNER_ON_CRISIS=0` (по умолчанию) — уведомления о кризисных сообщениях вам не приходят; `1` — приходят. `POLICY_URL` — ссылка на вашу политику обработки персональных данных. Пока её нет, в тексте показывается `[ССЫЛКА_ПОЛИТИКА]`. **До запуска для реальных людей политика должна быть.**

```bash
# 5. Запустить
python main.py
```

Напишите боту `/start`. Остановить бота: `Ctrl+C`.

Проверки (по желанию):
```bash
pip install -r requirements-dev.txt
python -m pytest
```

## 5. Команды

Для всех: `/start`, `/menu`, `/help`, `/news_on`, `/news_off`, `/stop_tips`, `/delete_me`, `/cancel`.

Только для владелицы (работают лишь с `OWNER_ID`; другим пользователям бот на них не отвечает):

| Команда | Что делает |
|---|---|
| `/give 123456789 telefon` | отправить PDF пользователю и записать выдачу. Продукты: `telefon`, `podrostok`, `uroki`, `nabor` (или `1`, `2`, `3`, `набор`). Через 3 дня бот сам спросит «Как прошла неделя?» |
| `/refunded 123456789` | отметить заявку на возврат выполненной — после того как вы сделали возврат в кабинете платёжного сервиса |
| `/summary` | сводка за последние 7 дней прямо сейчас (обычная приходит сама по понедельникам в 10:00 МСК) |
| `/stats` | сколько пользователей, подписчиков и невыполненных возвратов |

Команды «ответить пользователю от имени автора» нет: с клиентами общается только Виктория. ID пользователей — в еженедельной сводке. `/give` также закрывает заявку «выдать файл» этого пользователя.

## 6. Выдача после оплаты

### Сейчас (старт)
1. В платёжном сервисе (Продамус или ЮKassa) настройте товары так, чтобы после оплаты сервис **сам отправлял PDF на e-mail покупателя**. Ссылки на оплату пропишите в `.env` (`PAY_LINK_*`).
2. Если покупатель пишет «оплатила, файл не пришёл»:
   - покупка записана в боте → Виктория сразу присылает файл заново;
   - записи нет → Виктория даёт инструкцию (Спам, Промоакции) и просит e-mail оплаты. Заявка попадает в еженедельную сводку: найдите платёж по e-mail и выдайте `/give <user_id> <продукт>`.

Бот **никогда не просит данные карты** в чате. Оплата проходит только на странице сервиса.

### Потом: автоматическая выдача через вебхук (не реализовано, план)
Вебхук — это адрес, на который платёжный сервис сам сообщает «оплата прошла». Сервер для него в этой версии **сознательно не написан**: форматы уведомлений и способ проверки подписи нужно сверить с актуальной документацией сервиса, а ошибка здесь означает либо выдачу без оплаты, либо её отсутствие. Готов интерфейс в `payments.py`:

- `PaymentEvent`: кто оплатил (Telegram ID), что, сумма, ID платежа;
- `ProdamusProvider.parse_webhook` / `YooKassaProvider.parse_webhook`: заготовки с TODO, сейчас выдают ошибку «не реализовано»;
- `grant(event, storage, send_documents)` — уже работает и проверен тестами. Сверяет сумму с ценой, не выдаёт дважды за один платёж и проверяет, что пользователь запускал бота.

Что понадобится программисту:
1. **Домен и HTTPS** на сервере (nginx + бесплатный сертификат Let's Encrypt).
2. **Связать оплату с Telegram ID.** Кнопка оплаты в боте должна вести на ссылку, в которой зашит ID пользователя:
   - ЮKassa: создавать платёж через API с `metadata` (`tg_user_id`, `product`);
   - Продамус: дополнительный параметр ссылки — уточнить в документации.
3. **Небольшой веб-сервер** (например, `aiohttp.web`, он уже установлен вместе с aiogram) с адресом вида `/pay/yookassa`. Он принимает уведомление, вызывает `parse_webhook` и затем `grant`.
4. **Проверка подлинности.**
   - Продамус: подпись секретным ключом.
   - ЮKassa: перезапросить платёж по его ID через API и сверить статус и сумму; дополнительно ограничить IP отправителей.
   - Секретные ключи — только в `.env`.
5. **Тест** на поддельное уведомление: оно должно отклоняться.

## 7. Виктория на GigaChat — по желанию

Без ключа Виктория работает в **режиме готовых ответов** (`faq.json`): ищет ключевые слова в вопросе. Он покрывает каталог, выбор разбора, возраст, файл не пришёл, как открыть PDF, замену, возврат (сценарий `support.py`), «вы психолог?», «вы бот?», возражения «дорого», «есть в интернете», «подумаю». Если ответа нет, Виктория говорит «Этого в моей базе нет…», а вопрос (без user_id, e-mail и телефонов) попадает в еженедельную сводку.

Чтобы включить GigaChat:
1. Зарегистрируйтесь в личном кабинете GigaChat API (developers.sber.ru) и создайте проект GigaChat API.
2. Скопируйте **ключ авторизации** (Authorization key) в `GIGACHAT_AUTH_KEY` в `.env`.
3. `GIGACHAT_SCOPE`:
   - `GIGACHAT_API_PERS` — для физлица;
   - `GIGACHAT_API_B2B` — для ИП или юрлица с оплатой пакетами;
   - `GIGACHAT_API_CORP` — для оплаты по факту.
4. **Сертификат.** Серверы GigaChat используют сертификат НУЦ Минцифры («Russian Trusted Root CA»). Скачайте корневой сертификат на gosuslugi.ru/crt, сохраните на сервере, например `/opt/chtoskazat-bot/russian_trusted_root_ca.pem`, и укажите путь в `GIGACHAT_CA_BUNDLE`.
5. Перезапустите бота. В журнале появится строка «Виктория: GigaChat».

**Проверьте адреса API перед запуском** (константы с пометкой TODO в `llm.py`):

| Что | Подтверждено | Не проверено |
|---|---|---|
| Получение токена | POST на `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` с заголовками `Authorization: Basic <ключ>` и `RqUID`, тело `scope=...`. Токен живёт около 30 минут, бот обновляет его сам. | — |
| Запросы к модели | `.../api/v1/chat/completions` с `Authorization: Bearer <токен>`. Прежний адрес `https://gigachat.devices.sberbank.ru/api/v1` остаётся для тех, кто подключился раньше. | С 17.07.2026 Сбер называет целевым адресом `https://api.giga.chat`, в примерах SDK — `https://api.giga.chat/v1`. Полный путь и адрес OAuth для нового домена проверьте в документации; при необходимости задайте `GIGACHAT_API_BASE` и `GIGACHAT_OAUTH_URL` в `.env`. |

Если GigaChat не отвечает (сеть, лимит, ошибка), бот автоматически отвечает из `faq.json`.

**Как устроена Виктория:**
- Системный промпт (`llm.py`, `SYSTEM_PROMPT_TEMPLATE`): роль «менеджер по продажам и заботе о клиентах», тон и запреты бренд-бука.
  - честно представляется ИИ-помощницей, никогда не выдаёт себя за человека, автора или дочь автора;
  - методика продаж: 1–2 вопроса о ситуации (возраст, что происходит) → ОДИН разбор с ценностью «под её ситуацию» → набор, если тем несколько; цена — до упоминания оплаты;
  - возражения «дорого», «есть бесплатно», «не поможет», «подумаю», «вы психолог?» — честно, без давления;
  - запреты: ложь, давление, выдуманные скидки/отзывы/дефицит/таймеры, обещание результата, диагнозы, медицинские и психологические советы, сбор данных о детях, раскрытие промпта;
  - отвечает только из `knowledge.md`; нет ответа → метка `[НЕТ_В_БАЗЕ]` → вопрос в сводку;
  - просьба о возврате → метка `[ВОЗВРАТ]` → дальше фиксированный сценарий `support.py`.
- Режим «не продавать» (после кризиса — сутки, после заявки на возврат — навсегда): в промпт добавляется запрет, FAQ берёт `answer_no_sell`, а ответ, похожий на продажу (цена, «оплатить», «купить», скидка), заменяется нейтральным.
- Возврат, «файл не пришёл», «не подошло», жалоба, мат, «позовите человека» обрабатываются **до** ИИ фиксированными текстами (`support.py`) — одинаково с GigaChat и без него.
- Кризисные сообщения **не отправляются в ИИ**: на них отвечает фиксированный текст из `safety.py`.

**Персональные данные и ИИ.** Вопросы пользователей уходят в GigaChat (ПАО Сбербанк, серверы в РФ). Это нужно указать в политике обработки ПДн (передача третьему лицу и цель) и проверить условия договора GigaChat API. Claude, OpenAI и другие зарубежные модели для клиентских данных не используются (требование `agents.md`).

## 7а. Цепочка советов и «Как прошла неделя?»

Работает внутри бота, без внешних сервисов: очередь хранится в базе (таблица `scheduled_messages`), фоновая задача в `main.py` проверяет её раз в минуту. Тексты — в `texts.py` (раздел «Автоцепочка»), логика — в `followup.py`.

**Кому.** Только тем, кто дал согласие на обработку данных **и** нажал «Да» на вопрос о рассылке: это рекламные сообщения, на них нужно отдельное согласие. Ответили «Не нужно» или `/news_off` — цепочка не придёт.

**Цепочка после «10 фраз»** (время московское; каждое сообщение — с кнопкой «Не присылать советы»):

| Когда | Что |
|---|---|
| день 1, 19:00–21:00 | «Попробовали первую фразу?» — с какой из 10 фраз начать |
| день 2, 19:00–21:00 | короткий вымышленный пример + одна фраза из Разбора 1 |
| день 3, 19:00–21:00 | «Какая ситуация у вас сейчас?» и кнопки «Телефон и игры», «Грубит или молчит», «Уроки и учёба». По кнопке — карточка разбора (что внутри, 299 ₽, кнопка оплаты), под ней — набор за 690 ₽ |
| день 5, 19:00–21:00 | один мягкий повтор, только если покупки нет: «Больше напоминать не буду». Дальше цепочка молчит |

Как только человек что-то купил (выдача через `/give`), оставшиеся сообщения цепочки отменяются.

**«Как прошла неделя?»** — через 3 дня после `/give`, не ночью. Кнопки:
- «Стало спокойнее» — другие разборы; купившим один разбор — «набор со скидкой на уже купленный: ссылка». Ссылка берётся из `PAY_LINK_UPGRADE` в `.env`; пока её нет, в тексте видно `[ССЫЛКА_ДОПЛАТА]`.
- «Сложно, нужна помощь» — «10 фраз» ещё раз, другой разбор или набор, телефон доверия на случай опасности.
- «Не подошло» — «Выберите другой разбор — пришлю его вместо этого». Одна замена на покупку. Если PDF есть в `files/`, бот присылает его сам и записывает выдачу как замену (`source = swap` в таблице покупок). Если файла нет, бот ничего не записывает, а вам приходит техническое уведомление: положите файл, и человек сможет нажать кнопку ещё раз. Для набора вместо замены — подарок «Карта спокойного вечера» (`files/04-podarok.pdf`, один раз на покупку, `source = gift`).

В текстах цепочки и «Как прошла неделя?» нет возврата и «написать автору». Если человек сам напишет «верните деньги», Виктория ведёт сценарий возврата (раздел 8), заявка попадает в сводку.

**Тихие часы.** С 22:00 до 9:00 по Москве бот ничего из очереди не отправляет. Если бот был выключен и время прошло, сообщение цепочки переносится на ближайший вечер 19:00–21:00, а «Как прошла неделя?» — на 10:00.

**Когда бот НЕ отправляет:**
- сработал кризисный детектор: все продающие сообщения отменяются, 7 дней бот ничего из цепочки не шлёт, а кнопки ситуаций вместо карточки показывают текст помощи;
- у человека отметка **no_sell** (оформил заявку на возврат): цепочка и «Как прошла неделя?» не уходят никогда, карточки — только описание без цены и оплаты, рассылка новостей его исключает;
- человек нажал «Не присылать советы» или `/stop_tips` (отметка хранится в базе, таблица `followup_state`): отменяется и цепочка, и «Как прошла неделя?»;
- `/delete_me`: очередь и отметки удаляются вместе с остальными данными;
- человек заблокировал бота: при первой ошибке отправки бот ставит отметку и снимает всё из очереди. Отметка снимается, когда человек снова нажмёт `/start`.

**Как отключить.**
- Одному человеку: он сам нажимает `/stop_tips` или кнопку «Не присылать советы».
- Всем сразу: в `main.py` закомментируйте строку `scheduler_task = asyncio.create_task(scheduler_loop(...))` и перезапустите бота. Очередь останется в базе и не отправится.
- Убрать уже поставленные сообщения: `sqlite3 data/bot.sqlite3 "UPDATE scheduled_messages SET cancelled = 1, cancel_reason = 'off' WHERE sent_at IS NULL"`.

**Автовыдача через вебхук (план, раздел 6).** Когда её подключат, после `grant()` нужно вызвать `followup.on_purchase(...)`, как это делает `/give`. Иначе «Как прошла неделя?» после оплаты по ссылке не придёт.

## 7б. Еженедельная сводка владелице и возвраты

Каждый **понедельник в 10:00 МСК** бот присылает на `OWNER_ID` одно сообщение (`summary.py`, проверка в `scheduler.py`). При первом запуске сводка не шлётся — первая придёт в ближайший понедельник. Если бот был выключен в понедельник, сводка уйдёт сразу после запуска. Сводку за последние 7 дней можно запросить командой `/summary`.

Что в сводке:
- новых пользователей, покупок (записанных в боте), замен и подарков, заявок на возврат за неделю, число срабатываний кризисного сценария (только число);
- **возвраты к оформлению** — все невыполненные: user_id, e-mail оплаты, дата покупки, продукт, дата заявки;
- **кому выдать файл** после проверки оплаты (у человека нет записи о покупке в боте): user_id, e-mail, «файл не пришёл» или «замена → разбор»;
- **вопросы без ответа в базе** (до 15 штук) — без user_id; e-mail, телефоны, ссылки и @ники вырезаются ещё до записи в базу. Хранятся 35 дней. Добавляйте ответы в `knowledge.md` и `faq.json`.

Имён и переписки в сводке нет.

**Сценарий возврата** (возврат в маркетинге не упоминается, Виктория его сама не предлагает):
1. Клиент просит вернуть деньги → Виктория коротко признаёт и **один раз** предлагает замену кнопками (для набора — подарок «Карта спокойного вечера»; если покупки нет в боте — замену по e-mail оплаты).
2. Настаивает → не спорит, просит e-mail, на который была оплата.
3. Получила e-mail → заявка (`refund_requests`), отметка **no_sell навсегда**, продающие сообщения отменяются. Клиенту: «Заявку приняла, оформлю возврат на карту, с которой была оплата. Срок зачисления зависит от банка, обычно до 10 рабочих дней.»
4. Вы видите заявку в понедельничной сводке, делаете возврат в кабинете платёжного сервиса и пишете `/refunded <user_id>`.

> По закону о защите прав потребителей требование о возврате нужно удовлетворить в течение 10 дней. При сводке раз в неделю у вас остаётся около 3–9 дней — не откладывайте возвраты после понедельника. Покупки на Wildberries бот не возвращает: Виктория отправляет к правилам площадки.

## 8. Безопасность

Порядок обработки каждого текстового сообщения (`dialog.py`):

1. **Кризис** (`safety.detect_crisis`) проверяется первым, по всему тексту, даже если сообщение слишком длинное, человек превысил лимит или ещё не дал согласие. При срабатывании:
   - бот отправляет фиксированный текст: сочувствие, 112, телефон доверия 8-800-2000-122, «передано автору, но не ждите — позвоните» (текст не меняется решением владелицы; см. замечание ниже);
   - уведомление вам — **только при `NOTIFY_OWNER_ON_CRISIS=1`**, не чаще раза в 10 минут на одного человека; по умолчанию выключено;
   - **сутки бот этому человеку не продаёт**: кнопка «Разборы» снова показывает текст помощи, а Виктория получает указание не продавать;
   - в базе ставится отметка времени (без текста): **7 дней** не уходит ничего из цепочки советов и «Как прошла неделя?» (раздел 7а);
   - текст кризисного сообщения **в базу не сохраняется**, записывается только отметка.
2. **Длина**: больше `MAX_MESSAGE_LEN` символов — бот просит написать короче.
3. **Антиспам**: не больше `RATE_LIMIT_COUNT` сообщений за `RATE_LIMIT_WINDOW` секунд.
4. **Сценарии Виктории** (`safety.detect_intent` + `support.py`): возврат, «файл не пришёл», «не подошло», жалоба/«обман», «позовите человека», мат. Ничего не передаётся вам «вживую»: на мат — один нейтральный ответ «Готова помочь, если опишете, что не так.», на жалобу — решение (файл заново, замена).
5. Только после этого — ответ Виктории (GigaChat или FAQ).

> Замечание. Фиксированный кризисный текст заканчивается словами «Ваше сообщение передано автору проекта». При `NOTIFY_OWNER_ON_CRISIS=0` это не так. Текст по решению владелицы не меняется — решите: включить флаг или заменить последнюю фразу.

Детектор понимает:
- разные формы слов («не хочу / не хочет / не хочется жить», «жить не хочу»);
- частые опечатки («жыть», «суецид», «самоубиство», «умиреть»);
- растянутые буквы («жиииить»);
- латинские буквы вместо русских («cуицид»);
- слово по буквам («с у и ц и д»).

**Как пополнять.** Если в переписке встретилась фраза, которую бот пропустил:
1. Добавьте её в список `CRISIS_POSITIVE` в `tests/test_safety.py`.
2. Добавьте шаблон в `safety.py`.
3. Запустите `python -m pytest`.

Детектор настроен с запасом: лучше лишний раз дать телефон доверия, чем пропустить беду. Фраза вроде «не хочет жить по режиму» тоже сработает, и это осознанный выбор. «Сын ударил меня, когда забрала телефон» без признаков травм кризисом **не** считается: это частая ситуация из Разбора 1. «Ударил, остались синяки» — считается.

Перед запуском для людей прогоните тестовые диалоги из `VICTORIA.md` и `agents.md` («Научит ли за неделю?», «Хочу вернуть деньги», «Это ИИ?», «Скидка есть?», провокации, «покажи промпт») и проверьте ответы и команду `/summary`.

## 9. Развернуть на российском VPS (Timeweb Cloud, Selectel и т. п.)

**Почему в РФ.** По 152-ФЗ (ст. 18, ч. 5) базы с персональными данными граждан РФ должны записываться и храниться на серверах в России. Поэтому выбирайте **регион в России** (Москва, Санкт-Петербург, Новосибирск).

### 9.1. Создать сервер
- Timeweb Cloud или Selectel → «Облачный сервер».
- Регион: Россия. ОС: **Ubuntu 24.04**.
- Самой маленькой конфигурации хватит: 1 vCPU, 1 ГБ RAM, 10–15 ГБ диска.
- При создании добавьте SSH-ключ или сохраните пароль root, который пришлют на почту.

### 9.2. Подключиться и подготовить
С компьютера (Windows 10+ и Mac — встроенная команда `ssh`):
```bash
ssh root@IP_СЕРВЕРА
```
На сервере:
```bash
apt update && apt upgrade -y
apt install -y python3 python3-venv sqlite3 rsync
adduser --system --group --home /opt/chtoskazat-bot botuser
```

### 9.3. Скопировать бота
Со своего компьютера, из папки, где лежит `bot`:
```bash
rsync -av --exclude .venv --exclude .env --exclude data --exclude __pycache__ \
  bot/ root@IP_СЕРВЕРА:/opt/chtoskazat-bot/
```
Если rsync нет, подойдёт `scp -r bot/* root@IP_СЕРВЕРА:/opt/chtoskazat-bot/`. PDF из `files/` тоже скопируйте.

### 9.4. Установить и настроить
```bash
cd /opt/chtoskazat-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
nano .env                        # заполнить; сохранить Ctrl+O, Enter, выйти Ctrl+X
mkdir -p data backups
chown -R botuser:botuser /opt/chtoskazat-bot
chmod 600 .env                   # .env читает только владелец файла
```
В `.env` на сервере `DB_PATH` можно оставить пустым: база будет в `/opt/chtoskazat-bot/data/bot.sqlite3`.

Проверка вручную:
```bash
sudo -u botuser .venv/bin/python main.py
```
Напишите боту `/start`, затем остановите его `Ctrl+C`.

### 9.5. Автозапуск через systemd
```bash
cp deploy/chtoskazat-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now chtoskazat-bot
systemctl status chtoskazat-bot          # должно быть active (running)
journalctl -u chtoskazat-bot -f          # журнал в реальном времени, выход Ctrl+C
```
Бот сам перезапускается при сбое и после перезагрузки сервера.

**Важно:** бот должен работать **в одном экземпляре**. Не запускайте его одновременно на компьютере и на сервере с одним токеном, иначе Telegram вернёт ошибку конфликта.

## 10. Обновление

```bash
# со своего компьютера — новые файлы:
rsync -av --exclude .venv --exclude .env --exclude data --exclude __pycache__ \
  bot/ root@IP_СЕРВЕРА:/opt/chtoskazat-bot/

# на сервере:
cd /opt/chtoskazat-bot
sudo -u botuser sqlite3 data/bot.sqlite3 ".backup 'backups/before-update.sqlite3'"   # бэкап
.venv/bin/pip install -r requirements.txt          # если менялся requirements.txt
chown -R botuser:botuser /opt/chtoskazat-bot
systemctl restart chtoskazat-bot
journalctl -u chtoskazat-bot -n 50                 # проверить, что запустился без ошибок
```

Обновить библиотеки (aiogram и др.) — задача программиста. Порядок такой:
1. Поднять версии в `requirements.txt`.
2. Прогнать `python -m pytest` на компьютере.
3. Только потом выкладывать на сервер.

## 11. Резервная копия базы

База — один файл `data/bot.sqlite3`. Копировать его просто так, пока бот работает, нельзя (копия может оказаться битой). Используйте `sqlite3 .backup`.

Ежедневный бэкап с хранением 14 дней. На сервере выполните `crontab -e -u botuser` и добавьте строку:
```
15 3 * * * cd /opt/chtoskazat-bot && sqlite3 data/bot.sqlite3 ".backup 'backups/bot-$(date +\%F).sqlite3'" && find backups -name 'bot-*.sqlite3' -mtime +14 -delete
```

**Копии вне сервера** тоже храните **в РФ**: например, в объектном хранилище S3 того же провайдера (Timeweb/Selectel, регион Россия) или на своём компьютере в РФ. Скачать на компьютер:
```bash
scp root@IP_СЕРВЕРА:/opt/chtoskazat-bot/backups/bot-2026-11-22.sqlite3 .
```

**Восстановление:**
```bash
systemctl stop chtoskazat-bot
cp backups/bot-ДАТА.sqlite3 data/bot.sqlite3
rm -f data/bot.sqlite3-wal data/bot.sqlite3-shm
chown botuser:botuser data/bot.sqlite3
systemctl start chtoskazat-bot
```

Помните: в бэкапах остаются данные людей, которые потом нажали /delete_me. Поэтому старые бэкапы удаляются через 14 дней — укажите этот срок в политике.

Это не юридическая консультация. Финальные тексты согласия, политики и оферты проверьте с юристом.

  - как отозвать согласие: /delete_me.
- [ ] **Согласие** даётся кнопкой до отправки материалов, дата сохраняется. Согласие на рассылку — отдельное, с отпиской `/news_off`; на советы после «10 фраз» — отписка `/stop_tips`.
- [ ] **Данные детей не собираются.** Бот прямо просит не писать имя ребёнка и подробности, а ИИ запрещено их спрашивать. Если человек всё-таки написал, такие тексты могут попасть в журнал. Журнал хранится ограниченное время (`DIALOG_LOG_DAYS`) и удаляется по /delete_me. Можно вовсе отключить журнал: `LOG_DIALOGS=0`.
- [ ] **Кризисные сообщения** в базу не пишутся. Уведомления о них по умолчанию выключены (`NOTIFY_OWNER_ON_CRISIS=0`); если включите — не пересылайте их дальше.
- [ ] **Еженедельная сводка** содержит user_id и e-mail только для заявок, требующих ваших действий (возврат, выдача файла). Не пересылайте её дальше.

- [ ] `.env` (токен, ключи) не публикуется, права `600`. Если токен утёк: @BotFather → `/revoke`, затем впишите новый токен в `.env` и перезапустите бота.
- [ ] **Логи на сервере.** `journalctl` содержит технические сообщения aiogram и не содержит текстов пользователей.
